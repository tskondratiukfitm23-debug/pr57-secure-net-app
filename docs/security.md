# Механізми захисту

## 1. TLS
- `gencerts.sh`: кореневий CA RSA-4096 (5 років, `basicConstraints=CA:TRUE`) → серверний ключ **ECDSA P-256**,
  сертифікат на 398 днів, `keyUsage=digitalSignature`, `extendedKeyUsage=serverAuth`,
  SAN = `DNS:localhost, DNS:server, DNS:secure-server, IP:127.0.0.1` + IP з аргументу. Ключі мають права 600.
- Фактичне рукостискання (`client.py tls-info`, `openssl s_client`): **TLSv1.3, TLS_AES_256_GCM_SHA384**, обмін ключами X25519, підпис ECDSA/SHA-256.
- Клієнт довіряє лише `ca.crt`, перевіряє ланцюжок **і** ім'я хоста (SAN); мінімальна версія TLS 1.2. Перевірку не вимкнено ніде (`verify=False` відсутнє).
  Невідомий CA → `unable to get local issuer certificate (20)`, чуже ім'я → `Hostname mismatch (62)`; дані не передаються.
- Відкритий порт 8080 обслуговує лише `/health` і `/echo-http`; будь-який інший шлях по HTTP → `403 TLS required`.
  На HTTPS додається `Strict-Transport-Security`; на всі відповіді — `X-Content-Type-Options`, `X-Frame-Options`, `Cache-Control: no-store`.

## 2. Облікові записи
- Паролі — **bcrypt** (cost 12, унікальна сіль у кожному хеші). Політика: ≥12 символів, цифра, великі й малі літери.
- Для неіснуючого користувача перевіряється фіктивний хеш (однаковий час відповіді, немає перебору логінів); відповідь завжди `Invalid credentials`.
- Ролі: `user` → {echo, whoami, mfa}; `admin` → + {admin}. Роль для перевірки прав береться **з БД**, а не з токена.

## 3. JWT
| Параметр | Значення |
|---|---|
| Алгоритм | HS256 (дозволено лише його — `alg=none`/інші відкидаються) |
| Секрет | `JWT_SECRET` зі змінної середовища, ≥32 символи; у `prod` без нього сервер не стартує |
| access / refresh / mfa | 15 хв / 8 год / 5 хв |
| Обов'язкові claims | sub, role, typ, iat, nbf, exp, iss, aud, jti |
| Відкликання | denylist за `jti` (logout, ротація refresh, одноразовий mfa_token) |

Перевірені сценарії обходу (`client.py bypass`, `tests/test_app.py`): без токена, сміття, `alg=none`, змінений payload,
підпис іншим ключем, прострочений, refresh замість access, mfa_token замість access, валідний токен `user` на адмін-ендпоінт,
токен із `role=admin` для звичайного користувача — усі дають 401/403.

## 4. MFA (TOTP, RFC 6238)
`/auth/mfa/setup` створює секрет (160 біт, base32) і `otpauth://` URI (QR-код для Google/Microsoft Authenticator);
MFA вмикається лише після підтвердження правильним кодом. Вхід: пароль → `mfa_token` (5 хв) → `/auth/login/otp`.
Вікно ±1 крок (30 с), кожен крок можна використати лише раз (`totp_last`) — захист від повторного відтворення коду;
невдалі OTP рахуються в лічильник блокування.

## 5. Rate limiting
- **Token bucket на IP** для всіх запитів: 30 запитів «запасу», поповнення 15/с → понад ліміт `429` + `Retry-After`.
- **Логін**: ≤20 спроб/хв з одного IP; після **5** невдалих спроб за 5 хв обліковий запис блокується на 60 с, далі ×2 (до 1 год).
  Під час блокування навіть правильний пароль отримує 429. Успішний вхід скидає лічильник.
- Результати: brute force на `bob` — 5×401, далі 429; flood 300 запитів у 30 потоків — 33 пропущено, 267 відхилено (429),
  через 3 с легітимний запит знову обслуговується.

## 6. Журнали
JSONL (`server/logs/app.jsonl`), один рядок — одна подія: `ts` (UTC), `level`, `event`, `category`, `ip`, `user`, `path`,
`status`, `request_id`... Поля `password, pwd, token, otp, secret...` маскуються (`***`).
Категорії: request, auth, session, access, security, admin, error. Фільтрація: `GET /admin/logs?event=&category=&user=&ip=&since=&until=`
(лише admin) та `tools/analyze_logs.py` (зведення, топ порушників, алерти).

## 7. CI/CD (`.github/workflows/security.yml`)
На кожен push/PR: **Bandit** (SAST, падає на medium+; JSON-звіт — артефакт), **pip-audit** (`--strict`, вразливі залежності),
**pytest** (18 тестів), **E2E** (сервер + клієнтські сценарії TLS/JWT/rate limit).

## 8. Що виправлено порівняно з наданим шаблоном
| Проблема в шаблоні | Рішення |
|---|---|
| Секрет JWT за замовчуванням у коді | лише змінна середовища, ≥32 символи, обов'язковий у prod |
| Однаковий «фіктивний» bcrypt-хеш у `users.json` для всіх | хеші генеруються скриптом `create_users`, файл не комітиться |
| Rate limit рахував усі спроби, без блокування облікового запису | окремо: bucket на IP + лічильник невдач на користувача з експоненційним блокуванням |
| CORS `*` разом із credentials | CORS не підключено (клієнт — CLI, браузерний доступ не потрібен) |
| Пароль `alice/secret` захардкожено в клієнті | облікові дані лише з аргументів |
| Немає refresh/відкликання токенів, немає перевірки iss/aud/typ | ротація refresh, denylist jti, повний набір claims |
| TOTP без захисту від повторного коду | `totp_last`, одноразовий mfa_token |
| Bandit/pip-audit у CI з `\|\| true` (ніколи не падають) | CI падає на знахідках |
| У логи могли потрапити секрети | маскування чутливих полів |
